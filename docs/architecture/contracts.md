# Contracts v1

## Readiness/release contract (fail-closed foundation)

`GET /api/health/live` remains process liveness only:200 `{"status":"ok"}`. New `GET /api/health/ready` returns503 `{"status":"not_ready"}` unless **both** the fixed image metadata file contains exactly40 lowercase hexadecimal commit characters and trusted startup has installed a complete `app.health.Readiness` instance. Runtime environment variables, request query/header values and a dict claiming ready cannot supply the release identity. Every response is `Cache-Control:no-store`.

The immutable probe-map snapshot must contain exactly `database`, `auth`, `secrets`, `storage`, `worker`; all must return literal `True` on this request. No cached success or liveness/config-presence fallback. Cooperative async checks run concurrently with a two-second per-check budget. An expected `ProbeUnavailable`, timeout, cancelled child or unexpected task exception means503; unexpected task errors cancel/join siblings without exposing/logging raw diagnostics. Caller cancellation propagates. These deadlines are **not** preemption of blocking code or cancellation-swallowing adapters: each real adapter must use bounded read-only transport/DB operations itself and sanitize external errors.

Success is exactly200 `{"status":"ready","release":"<image commit>"}`, matching the Cloudflare consumer's expected approved commit. **No real probes are installed by current startup; even a stamped image remains503.** Fake positive probes exist only in tests. Required next slice: actual restricted DB/schema availability, configured Auth availability, protected secret-consumer state, private Storage and supervised worker/heartbeat adapters, then native outage/restart tests. No test-only probe registry or ready switch may enter production configuration. Closed upload/chat capabilities do not waive required probes.

The API Dockerfile's optional, non-secret `NOTEBOOK_RELEASE_SHA` build argument writes `/app/app/_release_sha` and the OCI revision label. Empty metadata is allowed only for foundation builds and cannot pass readiness; malformed nonempty metadata fails the build. This is build metadata, **not cryptographic source attestation**: trusted build→commit→final image digests→frontend artefact binding and scan/release approval remain separate mandatory gates. Do not mount over image metadata. The endpoint does not authorize tunnel activation, security acceptance or deployment.

## Wave 3 interfaces and implementation boundaries

Document/job/chunk persistence, provider execution and A5's upload-ledger/status database boundary are integrated. Upload/worker/chat/UI remain incomplete; capability flags stay off until the corresponding complete route and runtime gates are verified. Target HTTP contracts below include unsupported future operations, not an enablement claim or reduction of the PDF, vector and graph requirements.

### Documents and jobs

- `POST /notebooks/{id}/documents`: multipart `file`, plus optional `connection_id` and `index_profile_id` (both required together for embedding). Header `Idempotency-Key` required, 1–128 characters. The current closed TXT/MD HTTP slice requires exactly one raw header with ASCII grammar `[A-Za-z0-9._:-]{1,128}`; duplicate headers (including mixed casing), whitespace, commas and non-ASCII fail with fixed422 before body reception. This is deliberately narrower than the service's general key contract. Return 202 `{document,job}` only after original storage and durable job creation succeed. Repeated identical request returns the existing result; conflicting content/options returns 409. Limit actual streamed file bytes to 25 MiB, not just Content-Length. Editor/owner only. TXT/MD must be valid UTF-8 without binary/NUL content; PDF requires signature validation and isolated parsing. Display filename never becomes a storage path.
- `GET /notebooks/{id}/documents`: `{items:[{id,notebook_id,filename,version_id,status,error_code}]}`; status `queued|processing|ready|failed`. `DELETE /documents/{id}` revokes visibility immediately and schedules idempotent storage cleanup. `POST /documents/{id}/retry` retries the current failed version under the current actor's permission and explicitly selected own connection; never inherits another uploader's credentials.
- Original storage is a private Supabase bucket; server-generated object key `workspace_id/notebook_id/document_id/version_id/original`. No browser storage credentials or unrestricted public bucket. Authorized downloads via BFF; any signed URL lifetime at most 60 seconds. Missing storage configuration fails closed. Cross-service failures require compensation/reconciliation, not falsely successful jobs.
- A owns ORM classes `Document`, `DocumentVersion`, `IngestionJob`, `Chunk`, `IndexProfile` and migration 0003. Documents carry workspace/notebook, creator, display filename, current version and deletion timestamp. Immutable versions carry document/workspace/notebook, sequential version, media type, byte count, SHA-256, unique storage key and created timestamp. Scope must be enforced by composite FKs, not just application code.
- Job carries version/workspace/notebook, actor_user_id, nullable connection_id and index_profile_id, idempotency_key, status (`queued|running|succeeded|failed|cancelled`), attempts, available_at, lease_token, lease_expires_at, heartbeat_at, safe error_code and timestamps. Text extraction alone needs no model credentials; embedding requires both connection/profile. Retain connection ID as historical identifier on disconnect (no credential reference, no cascade deleting job history); runtime lookup must fail closed if absent/inactive/not owned by actor. No model work without that check.
- Claim uses an atomic conditional update or `FOR UPDATE SKIP LOCKED`, with fenced lease token, heartbeat, bounded retries and stale-lease recovery. Before claim, model call and publish recheck admission, membership/edit role, active document version and personal connection. Obsolete workers cannot publish after a lease is reassigned. Deletes/version changes invalidate pending work and exclude old chunks from retrieval immediately.
- Chunk carries version/document/notebook/workspace, ordinal, text, SHA-256, nullable page (PDF 1-based), start/end offsets within its page/text. Unique `(document_version_id,ordinal)`; ordered offsets and nonnegative ordinals. Initial text chunks target 1200 characters, 200 overlap, maximum extracted text 2 million characters and 500 PDF pages. All limits enforced before publication.
- Index profile is immutable notebook-scoped `{id,workspace_id,notebook_id,provider,model,revision,dimensions}` with positive bounded dimension. No credentials/owner connection in a shared profile. Vector persistence and graph tables follow in a separate A-owned migration once the actual vector runtime is verified; text-only is explicitly text-only, never reported as hybrid search.
- RLS: admitted current members read nondeleted document/version/chunk/profile data; owner/editor mutate. Job status may be exposed to members through sanitized document DTOs; raw jobs are actor-private, with owner/editor checks for mutation. Runtime cannot grant itself membership or use privileged generic SQL. Worker credential and lease publication boundary must be reviewed before enabling ingestion. Storage policies are separately verified on the actual Supabase schema; no fake Storage tables in application migrations.

### Gated actor-scoped dispatch seam

`app.workers.dispatch.dispatch_one(verified_identity, *, worker, selection=None)` is internal only. Its caller must supply Identity from the existing server-side verifier; constructing an Identity/UUID is not authentication. A fresh restricted direct-login session checks subject/admission/READ COMMITTED and selects at most one own canonical current queued/attempts0 TXT/Markdown job. Selection commits/closes before exactly one `TextWorker.run_one`; worker claim/revalidation resolves races. Safe outcomes preserve idle/not_claimed/yielded/succeeded/failed/lease_lost and original cancellation. No I/O/worker retry, running-expiry recovery, token reset or public actor selector. Injected SelectionFactory declares trusted finite pool/connect bounds; declarations are not enforcement of arbitrary injected Python.

Main dc34927 independently passes490default tests/Ruff on kube1/SCRAM. This proves the helper/test scope, not production actor issuance, registry, restart scheduling or real Storage. A sticky-cancelled queued tombstone may still be selected and atomically rejected without I/O, so fairness remains unresolved. No daemon/HTTP/cleanup consumer/capability enablement is included.

### Integrated connection discovery boundary (F4)

`POST /api/connections/{id}/test` and `PATCH /api/connections/{id}` now use the verified Identity and explicit injected discovery repository/service, not a request-lifetime DB Session. Each lookup/publication opens a fresh READ COMMITTED transaction, enforces direct `notebook_app` for both session/current principals, subject/email claims and admission; all transactions close before secret/model I/O. Existing execution guard revalidates after secret resolution, during cooperative discovery and after its result. Publication locks only the owned connection, checks the original snapshot/current admission, requires a conditional UPDATE returning a row, and returns success only after commit. No retries after external I/O or uncertain commit.

Disconnect remains effective at **committed** inactive/delete; its existing cleanup can delay commit. Publication winning the connection lock can precede disconnect. Admission deletion after the final UPDATE statement snapshot can race commit; no admission lock or atomic admission-at-commit guarantee. Cancellation is cooperative/best effort, not recall of sent bytes or proof that remote billing stopped. Unknown provider/driver errors produce fixed `discovery_unavailable` 503; trusted application statuses use only fixed literal codes/messages. SQL/secret references/errors are not returned. The scoped kube1 acceptance on immutable `276f1baa52cfaad812a1d47adaacc5c8e35d94ba` passed 30 actual restricted PostgreSQL/in-process ASGI HTTP cases plus 135 focused regression cases, with zero failures/skips and verified cleanup. It confirms the implemented direct principals, RLS/grants, committed202/204 revocation, lock ordering and conditional publication under synthetic external boundaries. See [F4 review](../review/disconnect-boundary.md). This is not live network/provider cancellation, ambiguous wire-COMMIT recovery or a stronger admission-at-commit fence; no model-job execution or production capability is enabled.

### Provider execution seam

- Preserve model discovery and connection management. Add typed messages and stream events in `app/providers`: `Adapter.stream(*,model,messages,max_output_tokens)` yields normalized text deltas and a terminal usage/finish event; `Adapter.embed(*,model,texts)` returns validated vectors with the actual model identity. Existing constructor remains compatible. Bound input/output, framing buffers, request deadline and batch size; no implicit retries after visible output.
- Implement native Anthropic Messages streaming, OpenAI-compatible streaming/embeddings and Ollama chat/embedding only where supported by official API documentation. Anthropic embeddings and Codex subscription are unsupported rather than silently rerouted. Explicit unsupported-operation errors, no fabricated capability/model/context metadata.
- A small connection execution service in `app/connections` takes authenticated actor ID and connection ID, verifies active ownership before secret resolution, resolves credentials server-side only, and calls the adapter. Rechecks for jobs and long-running operations must use fresh DB state, not a cached ORM object. No secret/key-bearing object escapes this boundary into jobs or DTOs.
- Cancellation closes upstream response/client; timeout, malformed protocol, rate-limit and credential errors produce sanitized application errors without request headers/body, provider raw text or secrets. No redirects, environment proxy inheritance, endpoint/account fallback, tools or model-generated code execution. Validate actual connected destinations against allowed addresses (close the DNS-check/connect gap) before treating model egress as production-ready.
- BFF chat SSE retains `delta`, `citation`, `done`, `error` events above; provider events are internal and do not constitute verified citations. B validates every citation against retrieved authorized chunks before exposing it. Never hold a request-scoped DB transaction open for the lifetime of an upstream stream.


All endpoints under /api. UUID identifiers. Error: {"detail": {"code": str, "message": str}}. Lists: {"items": [...]}. Unauthorized 401; forbidden 403; unavailable integration 503. No production auth mocks.

## Invitations, membership and personal providers

- GET /auth/admission: {admitted:true}; 403 means identity has no admission. Invite acceptance uses verified identity without prior admission.
- POST /invitations {email,workspace_id|null,role}: {id,token,expires_at}. Workspace owner for workspace invites; platform administrator for app invites. No email is sent. Tokens are returned once for explicit copying into /invite#token=... and stored hashed.
- POST /invitations/accept {token}: {workspace_id,invited_workspace_id}. Transactional verified email/current inviter/expiry/revocation checks; personal workspace exactly once.
- GET /workspaces/{id}/members: items {user_id,role}. PATCH/DELETE /workspaces/{id}/members/{user_id}; owner only, last owner protected.
- GET/POST /connections: metadata only / {provider_id,label,api_key}; provider IDs refer to administrator catalog.
- POST /connections/{id}/test: {models:[{id}],status:"ok"}; this verifies model discovery, not generation.
- PATCH /connections/{id} {model}: validates current model listing.
- DELETE /connections/{id}: 204 confirmed cleanup; 202 cleanup_pending preserves inactive metadata for retry. Other users cannot list, read, test or revoke the connection.
