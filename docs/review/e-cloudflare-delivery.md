- `deploy/cloudflare/routing.py:113–154` verifies zone/account, tunnel identity/configuration source, exactly one existing proxied CNAME with the reviewed ID/target, snapshot identity/version and owned service. Missing/conflicting DNS is refused, not adopted or repaired. No DNS mutation is implemented.
- `routing.py:72–103` detects canonical duplicates, case/trailing-dot aliases and conservative wildcard shadowing before the owned rule, requires a final exact404 fallback, and refuses owned path/override fields or global origin overrides. Existing unrelated rules/configuration are retained, not reconstructed from a reduced schema.
- `routing.py:156–171` rereads/fingerprints before deep-copying the entire current configuration and changing only the owned service. PUT readback requires matching configuration and a strictly newer version. Already-desired configuration does not cause another PUT.
- **Not CAS:** official Cloudflare SDK documents whole-configuration replacement and exposes no declared version precondition. A second read does not close the read/PUT race. `__main__.py:38–53,191–219` supplies a fixed, retained-inode local flock and requires `--exclusive-writer`; the operations document correctly requires every shared-tunnel writer to honor that lock and separately excludes Dashboard/other hosts/API writers, including Access changes. - `routing.py:173–190` rolls back from fresh state and changes only the owned service. Foreign changes observed after activation are preserved. Ambiguous PUT/readback failures occur outside the public-check compensation block: no blind undo/retry is issued. Conflicting owned service or drift is refused. Successful anonymous Access redirects do not prove authenticated edge propagation of a rollback.
