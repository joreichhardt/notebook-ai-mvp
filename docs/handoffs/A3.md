## Public persistence interface

Import `Document`, `DocumentVersion`, `Chunk`, `IndexProfile`, `IngestionJob` from `app.db.models`.

- Documents: UUID `id`, `workspace_id`, `notebook_id`, `created_by`, display `filename`, nullable `current_version_id`, nullable `deleted_at`, `created_at`.
- Versions: UUID `id`, `document_id`, `notebook_id`, `workspace_id`; positive integer `version`; `media_type`, `byte_count` (1..25 MiB), lowercase 64-hex `sha256`, unique `storage_key`, `created_at`. Media types PDF/plain/markdown only. Exact key: `workspace/notebook/document/version/original`.
- To create: choose document/version IDs server-side, insert Document with current_version_id already set, flush it, then insert Version and flush within the SAME transaction. Deferred composite current-version FK permits this ordering and validates at commit. To replace: lock Document, set new current_version_id, insert next Version within that transaction. `(document_id,version)` is unique; caller allocates sequential next value under document lock (DB enforces positive/unique, not gaplessness). Versions cannot be updated, including through privileged fixture connections.
- Chunks: scoped IDs plus `ordinal`, `text`, `sha256`, nullable 1-based `page`, `start_offset`, `end_offset`, `created_at`. Offsets count characters, and end-start equals text length. Ordinal nonnegative; `(document_version_id,ordinal)` unique. Scalar limits 2m chars/500 pages enforced; aggregate extracted text size, parser boundaries, 1200/200 chunking target and content/hash validation remain worker responsibilities before publication.
- Profiles: scoped UUID IDs, provider catalog ID in `provider`, `model`, `revision`, dimensions 1..65536, created_at. Immutable metadata, no credentials/connections, unique full notebook profile identity. No vectors or graph DDL in this migration; text-only must be described as text-only.
- Jobs: scoped version IDs, `actor_user_id`, paired nullable `connection_id`/`index_profile_id`, actor+notebook unique idempotency key (1..128), `status`, attempts 0..5, scheduling/lease/error/timestamp fields. Identity/options immutable; attempts cannot decrease. `connection_id` intentionally has NO FK: disconnect retains historical ID, never secret reference. Retry under a different connection creates a new job/key; it cannot mutate prior execution identity. Application must compare request content/options on idempotency conflict and return 409 when conflicting.

## Authorization and deletion

Forced RLS for all five tables. Admitted current members read active documents/current versions/current chunks and notebook profiles; owner/editor writes only. Raw jobs remain actor-private even for another owner/editor, with writer membership required to mutate. Connection-backed job mutation additionally checks active connection ownership and matching profile provider; actual supported model/revision/dimensions must be validated at provider execution, not inferred from this metadata check. Removal of admission/membership, viewer demotion, old versions, deleted documents and disconnected connections immediately prevent new job claims/publication updates.

Soft delete is `SELECT public.notebook_delete_document(:document_id)` under ordinary transaction-local actor context: true means newly tombstoned, false means absent/already deleted/unauthorized (no existence disclosure). PostgreSQL SELECT visibility rejects ordinary UPDATE to a hidden new tuple, so this single-purpose function is SECURITY DEFINER with fixed pg_catalog search_path, qualified objects, no PUBLIC execute, and a dedicated NOLOGIN/NOSUPERUSER role holding only SELECT on documents/admissions/membership and UPDATE(deleted_at) on documents. No runtime membership in that role, generic SQL/RPC or worker privilege escalation. Negative tests connect directly as notebook_app and verify SET ROLE denial (a superuser SET ROLE fixture would not prove this).

Tombstoning immediately hides document/version/chunk rows; old jobs remain actor-private history but cannot mutate/publish. Pending/stale work is logically invalidated, not physically rewritten to cancelled. Original cleanup/reconciliation needs a separately reviewed narrow service boundary: never make the whole worker BYPASSRLS. Deleted versions/storage keys are intentionally not exposed through runtime RLS. Full storage deletion and Supabase Storage policies are NOT implemented here. Existing hard delete grants permit authorized content cascade; HTTP DELETE should use the tombstone function so cleanup information is retained.

## Lease helpers and safe execution boundary

`app.db.leases` exposes:

```python
claim_job(session, job_id, *, lease_seconds=60) -> UUID | None
heartbeat_job(session, job_id, token, *, lease_seconds=60) -> bool
lock_job_for_publish(session, job_id, token) -> bool
finish_job(session, job_id, token, *, status, error_code=None) -> bool
```

All run as invoker, notebook_app, short READ COMMITTED transactions, fresh trusted actor context set transaction-locally. They never set context/role, commit, resolve credentials, dispatch workers or execute arbitrary SQL. Lease duration bounded 1..300 seconds. Atomic SKIP LOCKED claim of a specific job permits queued or expired-running work, available_at reached, attempts<5; reclaims generate fresh tokens and increment attempts. Late heartbeats and obsolete completion tokens fail. Caller supplies only trusted actor-scoped job IDs from a reviewed dispatch source: global actor/job discovery and worker identity issuance are intentionally NOT implemented.

Execution protocol:

1. Claim under actor context, commit immediately. No DB transaction held during parsing/provider network I/O.
2. Recheck execution authorization in a NEW transaction before model work; a heartbeat invokes the fresh writer/connection RLS and returns false on revocation. C3 must independently resolve fresh active own credentials and validate model/profile compatibility; never reuse cached ORM authorization. Do not silently use uploader/owner credentials.
3. For publication, open transaction, set actor context, `lock_job_for_publish`; false means rollback. This locks the active document before the job, excluding concurrent tombstone/version changes and lease reassignment. Insert all chunks in that SAME transaction; call `finish_job(..., status='succeeded')` LAST; false means rollback ALL inserted chunks. Commit only if true. Explicit finish also rechecks clock and job writer/connection RLS.
4. Provider/permission revocation racing an already-open DB statement follows PostgreSQL READ COMMITTED snapshot semantics; recheck each stage, do not treat long-held cached context as authorization. External call cancellation remains worker/provider work.
5. For retry same execution identity after a failed job: ordinary actor-scoped conditional UPDATE status='queued', available_at=:backoff, error_code=NULL, updated_at=clock_timestamp() WHERE id=:job AND status='failed' AND attempts<5. Never reset attempts. Changed actor/connection/profile means a new job and explicit idempotency key. A five-attempt exhausted job requires a separately authorized fresh retry request, not automatic unlimited recovery.

These are cooperative internal Python primitives, not a browser-granted lease RPC. Direct authorized writer SQL can write chunks: DB schema alone is not an end-to-end ingestion fencing boundary. Review B3's transaction composition, trusted dispatch/actor selection, cleanup and quotas before enabling ingestion.
