# A2 — invitations, membership, personal provider schema

Base a34c43b. Adds real verified-account invitation creation/acceptance, owner-only member management, local verified-account administrator bootstrap, ProviderConnection model and migration 0002 with owner/admission RLS.

Parent includes app.auth.invitations.router. API: POST /api/invitations {email,workspace_id|null,role} returns {id,token,expires_at}; POST /api/invitations/accept {token} returns {workspace_id,invited_workspace_id}. GET/PATCH/DELETE /api/workspaces/{workspace_id}/members[/{user_id}]. GET /api/auth/admission returns admitted:true or 403 admission_required. All writes Origin + CSRF. Session identity remains separate from admission; verified-account auth dependency is sufficient only for acceptance.

SQL RPCs owned by dedicated NOLOGIN notebook_membership BYPASSRLS role with minimal table grants, fixed pg_catalog search_path and fully qualified table names. EXECUTE revoked from PUBLIC, granted only notebook_app. Do not grant membership in privileged role. Runtime sets verified UUID/email transaction-locally; RPCs are not exposed to browser Supabase roles. Migration needs administrative ability to create BYPASSRLS role. Role has no schema CREATE after setup.

Acceptance locks user and invitation, checks email, expiry, revocation, inviter admission/current authority; repeat same identity idempotent, another identity fails. Personal workspace unique per user. Workspace row lock serializes membership writes and last-owner protection. Owner demotion/removal revokes their open workspace invites. Existing member acceptance does not silently elevate role.

Bootstrap: PYTHONPATH=backend NOTEBOOK_MIGRATION_DATABASE_URL=<protected config> uv run python -m app.auth.bootstrap --email <explicit email>. Requires existing auth.users verified record; refuses once platform_admins nonempty. No public endpoint or default credentials.

ProviderConnection in app.db.models: requested id,user_id,provider_id,label,secret_id,model,status,created_at,last_tested_at. Only secret references; owner/admission RLS. No extra dependencies.

25 tests pass with NOTEBOOK_TEST_POSTGRES_URL=postgresql://jre@127.0.0.1:55439/postgres uv run pytest backend/tests/auth -q; real migration and RLS, expiry/email/revocation, inviter permission, last-owner protection, concurrent idempotent acceptance, foreign provider access. Root cluster remains isolated. Tests use disposable DB and create synthetic fixtures. No production tests or deployment.

Still pending: new-account registration/Google OAuth controlled correlation, invitation listing/manual revoke UI, profile emails in member lists, audit events, invitation rate limits, complete user lifecycle and full RAG schema. These remain release blockers; existing verified accounts can now bootstrap and accept invitations. API capabilities should mark registration/oauth unavailable explicitly.
