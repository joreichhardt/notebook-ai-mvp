# D2 · Sharing and personal model connections

Branch `agent/frontend`; baseline `a34c43b`.

## Delivered

- Removed roadmap/development/release notices and unsupported source/chat/OAuth/recovery controls. Empty states describe user actions only.
- Capability discovery through `GET /api/capabilities` gates password login, invitations and owner member management. Registration/OAuth/recovery remain hidden.
- Admission check `GET /api/auth/admission`: 403 gives an invitation instruction, other errors remain retryable service errors. Session identity alone no longer opens workspace UI.
- Invitation links use `/invite#token=...`. Token is read into memory and immediately removed from address bar, never persisted. Login preserves it in memory; acceptance is explicit and uses authenticated CSRF request. After acceptance session/admission reload. Page reload before acceptance requires reopening the link.
- Owner member list, role changes and confirmed removals; invitation creation tied to recipient email and selected workspace/role. Copy link is an explicit action. No email send.
- Personal connections: load only catalog providers, save API key, clear secret form on submission, test model listing, select model and confirm disconnect. No arbitrary endpoint field, no provider key in local storage, no subscription buttons without backend support.
- Catalog empty state asks operator to enable a provider; service failures give retry action without development details.

## API agreement

Auth A: GET `/auth/admission`, POST `/invitations`, POST `/invitations/accept`, GET `/workspaces/{id}/members`, PATCH/DELETE `/workspaces/{id}/members/{user_id}`. Members permit optional email label; user ID fallback is retained if absent.

Provider C: GET `/providers`, GET/POST `/connections`, POST `/connections/{id}/test`, PATCH `/connections/{id}` with model, DELETE connection. Model-list test does not generate text. Global default selection has no backend contract and is not displayed.

Parent: `/capabilities` response `{auth:{password_login,...},invitations,members,...}`.

All writes use existing X-CSRF-Token and same-origin credentials. Only safe fixed frontend error strings are shown, not raw upstream diagnostics.
