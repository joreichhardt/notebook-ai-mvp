## Interfaces currently implemented

```python
from app.ingestion.text import read_text_upload, chunks
upload = await read_text_upload(upload_file, "notes.md", "text/markdown")
# Actual bytes <=25MiB; UTF-8/no binary/NUL; extracted text <=2m characters.
# upload.filename is display-only; never use it as a Storage path.
parts = chunks(upload.text)  # deterministic offsets and SHA-256

from app.documents.storage import StorageConfig, SupabaseStorage, ObjectScope
# Main loads a protected token into SecretStr; only trusted I/O receives it.
store = SupabaseStorage(config, authorize=fresh_scoped_authorizer)
# scope holds four UUIDs from durable trusted rows, not arbitrary browser keys.
original = await store.read(actor_id, scope)
await store.put(actor_id, scope, original, "text/markdown")
# Authorization runs before bucket inspection, before object I/O and after it.

from app.workers.text import TextWorker
worker = TextWorker(restricted_notebook_app_engine, storage=config)
result = await worker.run_one(actor_id=trusted_actor_id, job_id=trusted_durable_job_id)
```

`run_one` is an **explicit trusted Python seam**, not a browser route, global job scanner or production dispatcher. Actor identity issuance belongs to the trusted caller; ordinary queries connect as `notebook_app`, verify exact non-superuser/NOBYPASSRLS role, set transaction-local actor, check admission and set 3s SQL/1s lock timeouts. Claim commits before external I/O; fresh heartbeat/source/member/lease checks bracket each stage. Heartbeat loss cancels I/O and discards output. Each run uses immutable durable source metadata, validates original byte count/hash, decodes bounded text and atomically composes source/job lock, all chunks, flush, finish **LAST**, then commit; false finish raises and rolls all chunks back. Chunks use deterministic UUID5(version,ordinal). Cancellation before publication closes I/O and fenced-cancels the job; the short synchronous publication transaction is the cancellation/commit linearization boundary. Claim attempts remain bounded by A3's five-attempt ceiling; crashes recover only through trusted re-invocation after lease expiry, not an autonomous retry dispatcher.

Actor concurrency is cooperatively serialized by transaction advisory lock with at most two unexpired actor-private running jobs. This is **not** a notebook-wide quota: actor-private job RLS cannot count other uploaders. Main accepted limits 10 outstanding actor/notebook, 50 notebook and active 2 actor/4 notebook as targets; A5 reserve aggregation and a reviewed cross-actor claim boundary remain enablement gates. No RLS widening or generic privileged query is used.

## Agreed upload protocol / A5 dependency

Coordinator decisions `msg_577087d4e1a5`, `msg_aea145391e57`, `msg_30c3149246d4`:

1. `notebook_app` reserves immutable intent (same idempotency content/options => same result, mismatch =>409) and commits, before any external write. No source/claimable job exists yet.
2. Separate trusted `notebook_storage_io` narrowly claims that exact durable intent and commits. No application-table reads, generic SQL, app role inheritance or broad RLS bypass.
3. Renewed current actor/intent/lease checks precede every bucket/object action. Private-bucket check, **non-upsert** exact-key POST with 30s overall HTTP deadline; bounded readback compares actual SHA/bytes. Lease must cover the entire write+verify window or be explicitly fenced-renewed; never confirm after expiry.
4. Narrow I/O receipt confirmation; actor finalizes version+job atomically after renewed permission and source CAS; commit before 202. Never return accepted for partial Storage/DB state.
5. Ambiguous timeout/revocation/DB failure stays durably discoverable for reconciliation. Never key-reuse after expired writer or claim crash cleanup from rollback/best-effort DELETE. A late server-side PUT can outlive client timeout/lease expiry: B/E must establish quiescence/absence checks and retained tombstone revisits; **not solved by this adapter**.

Provisional A5 code review observation sent to main `msg_68ea215a18bb`, acknowledged `msg_7f360878260c`: finalization read `intent.state` before acquiring notebook lock, so a concurrent replayer could reuse stale `stored` and attempt duplicate INSERT. Main forwarded request for fresh read after lock and real two-session exactly-once regression; **not an integrated-candidate finding** and B did not modify A files.

Expected A5 Python interface is provisional until its actual commit: `reserve_upload(session,notebook_id,*,idempotency_key,filename,sha256,byte_count,media_type,...) -> immutable UploadIntent`; narrow `claim_upload_io/confirm_upload_io`; `finalize_upload(session,intent_id) -> IDs`. A5 owns all ORM/DDL, source lifecycle and sanitized member-visible processing status; B will not duplicate these objects. Existing jobs remain actor-private. No member status may be fabricated from absence of another actor's raw job.
