### Lifecycle impact / transaction boundaries

- **Reserve:** counts noncancelled live reserved/stored or finalized queued/running intents, actor+notebook10/notebook50. Idempotent reserve replay retains IDs and does not acquire another slot. Gate/capacity error aborts the transaction before external I/O. B3 can retain its immutable validated bytes and retry only this short DB operation with the original idempotency key.
- **Claim upload I/O:** unchanged single-use `write_token IS NULL` and bounded lease/intent expiry (`0005_upload_lifecycle.sql:73–83`), with0006 gate inserted into fixed RPC. Commit claim before `store.put`. Busy retry is safe only after proven transaction rollback; never replay PUT because of a later DB error, and never blindly retry an ambiguous successful commit.
- **Receipt:** unchanged token/hash/byte/lease-fenced `confirm_upload_io` (`0005:84–94`), now gated. After PUT+readback, retry only the receipt DB transaction with those already-verified immutable facts; no re-PUT/re-read inside that retry. A rollback leaves the reservation/key discoverable for reconciliation. Expired receipt remains false/unavailable, not an invitation to obtain a new writer token.
- **Finalize:** B3 already owns a short transaction containing current authorization, source/version/job inserts, the final verifier, DTO selection and commit (`service.py:288–308`; A5 `uploads.py:127–200`). Gate acquired before notebook row lock; fresh post-lock intent reread preserves concurrent replay. Mirror requires exact canonical job/version/workspace/notebook/actor/idempotency binding, null connection/profile and initial queued/0/no lease (`0006:127–140`); existing0005 deferred guard still enforces receipt/finalized coupling. Finalize may temporarily mirror queued while intent is stored inside this transaction; only atomic commit makes accepted work visible. Any error rolls back the new document/version/job/status mirror together, leaving a previously committed stored receipt replayable without Storage I/O.
- **Worker claim:** canonical finalized job only; running slots actor-global2/notebook4, fresh token and attempts+1, bounded5. Mirror runs AFTER existing processing-status trigger (`0006:117–175`), so capacity/busy/error rollback preserves job attempt, token, version projection and mirror atomically. B3 must not construct Storage until this transaction commits; its current ordering already does so.
- **Heartbeat:** fresh whole short transaction, same token/attempt count, never renew expired/reassigned token, bounded nondecreasing expiry. Busy is not proof of lease loss; retry only within a short bounded deadline that leaves lease margin. If that budget expires, stop further I/O/publication and yield honestly, retaining the logical lease until expiry unless a separately successful fenced finish ends it.
- **Publish / finish / cancel:** retain B3's single transaction of source/job locking, all deterministic chunks, flush, fenced finish LAST, commit (`text.py:138–174`). On busy retry, rerun this **whole DB transaction** with the already-decoded parts, not only `finish_job` and not the Storage/decode pipeline. False fence must roll back all chunks. Explicit fenced failed/cancelled terminal transition from a live valid lease clears active occupancy; revocation/deletion-triggered cancellation instead preserves the mirrored live lease. Bounded cleanup contention must not mask the caller's original cancellation or claim success; an expired token cannot be terminally finished or renewed.
